# COUPLING — 全站必经点与文件间契约

> 读法：动下面清单里的文件、或改任何带「两处同改」约束的值之前读本篇。

结论来自一次四路并行的耦合扫描（组件 / 客户端脚本 / 构建期数据 / 后台）：依赖图是无环分层，后台自包含，局部改动不外溢；风险集中在下面的必经节点与少数人工维护的契约上。

## 必经点清单

| 文件                                       | 为什么必经                                                                  | 写坏后的爆炸半径                                                        |
| ------------------------------------------ | --------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `src/layouts/BaseLayout.astro`             | 全站唯一壳层，9 个前台页面全部经过                                          | 全站 + 所有全局 css / js 入口                                           |
| `src/lib/posts-data.ts`                    | 全仓唯一 `getCollection` 入口，所有前台页面构建期等它                       | 异常 = 构建失败（fail fast）；口径错 = 上线后静默 404                   |
| `src/lib/posts-views.ts`                   | 文章视图口径（`posts` / `allPosts` / `chronological` / `tags` / `allTags`） | 口径错构建全绿，上线后静默坏链                                          |
| `src/lib/category.ts`                      | 扇入最大，唯一被构建侧与浏览器侧同时 import 的 lib 模块                     | 塞构建期依赖炸客户端构建；塞浏览器 API 炸 frontmatter；逻辑错切页后才露 |
| `src/data/site.ts`                         | 前台 7 处 + 后台 3 处共用，站点标题 / OG / RSS / 评论参数 / 后台设置全挂它  | 结构错构建期炸；取值错运行时静默                                        |
| `src/assets/js/posts/posts-shell.ts`       | 文章区切页编排枢纽，四个子件都挂在它下面                                    | 全部 /posts 页的搜索框 / 左缘条 / 行状态同时错位                        |
| `src/pages/admin/_admin/AdminLayout.astro` | 后台扇入 11，全部后台页面经过                                               | 后台 11 页全灭，不外溢前台                                              |

**动清单内文件的守则**：必须跑完整 `pnpm verify` + `pnpm build`，并抽查产物（页面数、切页、图片优化）；「改动很小」不是跳过理由（AGENTS §9）。

## 文件间「两处同改」契约

| 契约                                              | 位置                                                                       | 只改一处的后果                                       |
| ------------------------------------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------- |
| frontmatter 缺字段默认值双拷贝                    | `src/content.config.ts` 的 transform ↔ `src/lib/posts-views.ts` 的默认映射 | 构建通过，两层取到不同默认值                         |
| 版面同值（768/769、850/1150/1151 断点与导航高度） | 刻意不抽共享常量，推导与分批表见 `docs/reference/CSS.md` 的「断点」节      | 版面错位；改某处只同步同一条版面规则的其它处，不拉齐 |

## 后台 → 全站的唯一跨墙通道

后台「网站设置」的 8 个页面在运行时通过 GitHub API 直接改写 `src/data/` 目录下的数据文件（见 `src/pages/admin/_admin/js/pages.ts` 注释）。这是后台影响前台的唯一路径，也是唯一绕过本地验证的路径：经它改出的数据文件，在下次构建前必须过一次 `pnpm build`。
