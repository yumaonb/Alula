# 架构

一句话：**全部在构建期生成静态 HTML，运行时的 JS 只负责交互与视觉，不负责取内容。**

---

## 渲染模式

`astro.config.ts` 里没有配 adapter，是纯静态生成（SSG）。构建产物 `dist/` 可直接托管。
运行时的外部请求只有两处：giscus 评论区（浏览器直接请求）和 GitHub API（客户端带 localStorage 缓存）。

后台（`/admin/`）同样没有服务端：它用浏览器直接调 GitHub API 读写仓库。令牌只存在页面内存里，
不写任何浏览器存储，刷新即失效；写操作走 Git Data API，把一批改动打成一个提交。详见下面的「后台」小节。

## 数据流

```
src/content/posts/**/*.md
        │  构建期扫描（glob loader，content.config.ts）
        ▼
getCollection('posts')  →  CollectionEntry[]（有 id / body / data）
        │  lib/posts-data.ts → buildData()
        ▼
BlogData { meta, posts, allPosts, chronological, entries, categoryTree, tags, allTags }
        │
        ├── pages/posts/index.astro        列表页
        ├── pages/posts/[...slug].astro    文章页 + 分类页
        ├── pages/posts/tag/[tag].astro    标签页
        ├── pages/posts/rss.xml.ts         订阅源（/posts/rss.xml）
        └── pages/sitemap.xml.ts           站点地图（/sitemap.xml）
```

| 文件                              | 职责                                                                                                                                                                                                                                                                                                                                                         |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `src/content.config.ts`           | 集合定义：`glob` loader 扫 `src/content/posts/**/*.md`；schema 校验 frontmatter 并补默认值（`title` / `tags` / `pinned` / `hidden`）                                                                                                                                                                                                                         |
| `src/lib/posts-data.ts`           | 数据入口。`loadBlogData()` 把所有文章整理成 `PostItem[]`（排序、字数、分类链），并读出分类元数据。**模块级缓存，一次构建只算一次**。`posts` 与 `allPosts` 的差别见下                                                                                                                                                                                         |
| `src/lib/category.ts`             | 纯函数：分类树、分类链、分类/标签 URL、日期格式化、分类匹配、可见性过滤，以及「从 URL 反查当前分类/标签」（`postPathSegments` / `activeCategoryOf` / `activeTagOf`，构建期首屏与客户端切页共用这一份）。不碰数据源，可单独测                                                                                                                                 |
| `src/lib/content-image.ts`        | 文章图片模块表：`contentImageGlob`（`src/` 下图片的 glob）+ `resolveContentImageKey(basePath, src)`（相对路径 → glob 键）+ `imageKeyToSourcePath(key)`（glob 键 → 源文件路径）。文章页 `ImageWrapper.astro` 与订阅源 `pages/posts/rss.xml.ts` 共用，改扩展名白名单只改这里                                                                                   |
| `src/pages/posts/[...slug].astro` | 一个文件同时处理**文章页**和**分类页**（靠 `props.type` 区分）                                                                                                                                                                                                                                                                                               |
| `src/pages/posts/rss.xml.ts`      | 订阅源：`@astrojs/rss` 把同一份 `BlogData` 输出成 RSS 2.0，条目顺序与列表页一致；每条输出 `description` 摘要（不塞全文，订阅源体积更小）；有封面 `image` 时输出 `enclosure`（封面解析走 `lib/content-image.ts` 的 `resolveCoverImage`，与分享卡同一处）；站点地址取自 `data/site.ts`；`lastBuildDate` 取最新一篇的 `pubDate`（不是构建时刻），保证产物可复现 |
| `src/pages/sitemap.xml.ts`        | 站点地图：同一份 `BlogData` 输出 `/sitemap.xml`；范围 = 固定顶层页 + 可列出文章（`posts`，不含隐藏）+ 分类页（与 `[...slug].astro` 路由同来源）+ 标签页（`allTags`）；`lastmod` 取文章日期；后台与 404 不进                                                                                                                                                  |

### 对外分享卡与内容许可

- **分享卡**：`components/layout/PageMeta.astro` 输出 `og:*` 与 `twitter:*`。标题与描述由 `BaseLayout` 算好（`pageTitle` / `pageDescription`）传进去，组件只负责拼绝对地址与卡片类型——绝对地址用 `data/site.ts` 的 `site.url`（含协议）拼。文章页的封面由 `lib/content-image.ts` 的 `resolveCoverImage` 解析（与订阅源 `enclosure` 同一处，两边各写一套时改一处另一处会静默失效）；public 里的文件会先确认存在，写错的路径不出现在卡片里。
- **内容许可**：`data/site.ts` 的 `contentLicense` 是唯一来源——文章页「许可协议」卡与页脚 `footerCopyright`（RSS 的 `<copyright>` 也用它）都从这里取。三处不许各写各的，否则会出现同页两种互斥授权。

### 关键约定

- **分类 = 目录路径**（`PostItem.category` 形如 `devnotes/css`），显示名来自该目录的 `index.json`。
- **`PostItem.slug` 就是集合条目的 `id`**：相对 `src/content/posts/` 的无扩展名路径，同时也是路由参数与 URL 尾段（`/posts/devnotes/css/at-rule/`）。
- **`entries` 与 `posts` 是两份视角**：`posts` 是加工过的列表项，`entries` 是原始条目（文章页要拿它 `render()` 出正文与标题树）。
- **`posts` 与 `allPosts` 也是两份视角**：`posts` = `allPosts` 去掉 `hidden: true` 的文章，**一切"列出来给人看"的地方都用 `posts`**（列表页、分类页、标签页、分类树、标签云、RSS、站点地图、上下篇）。`allPosts` 只用来生成路由（文章路由与**标签路由**，见下条）与取当前文章，这样隐藏文章直链可访问、却不出现在任何列表里。新增"列出文章"的地方时，选错这个变量就会把隐藏文章漏出去。

- **`posts` 的顺序是「置顶优先、再按日期倒序」，只适用于列表展示**。凡是判断「谁比谁新」的地方都不能用这个顺序：上下篇走 `chronological`（`posts` 的纯日期倒序视图），订阅源的 `lastBuildDate` 取全部条目里最大的 `pubDate`。用列表顺序会让一篇置顶的旧文章把「上一篇（较新）」和「最后更新」一起翻到错误方向。
- 分类页路由同时来自两个来源：有 `index.json` 的分类目录，以及每篇文章所在目录的所有祖先目录（**用 `allPosts` 遍历**——隐藏文章的面包屑指向自己的分类页，那条路由必须存在）。标签路由同理取 `allTags`（`allPosts` 的标签并集）——隐藏文章页头也渲染标签链接，路由缺一条就是 404；页面正文仍只列 `posts`，某标签只被隐藏文章用过时列表为空。

| URL                                                      | 文件                                                                                    |
| -------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `/`                                                      | `pages/index.astro`                                                                     |
| `/about/` `/friends/` `/projects/` `/sponsor/` `/tools/` | 同名页面                                                                                |
| `/posts/`                                                | `pages/posts/index.astro`                                                               |
| `/posts/<分类路径>/`                                     | `pages/posts/[...slug].astro`（`type: 'category'`）                                     |
| `/posts/<分类路径>/<文件名>/`                            | `pages/posts/[...slug].astro`（`type: 'post'`）                                         |
| `/posts/tag/<标签>/`                                     | `pages/posts/tag/[tag].astro`                                                           |

| `/sitemap.xml`                                           | `pages/sitemap.xml.ts`（站点地图：顶层页 / 文章 / 分类 / 标签，不含隐藏文章）           |
| 不存在的路径（404）                                      | `pages/404.astro`（自定义 404 页，noindex；`/admin/` 下的路径整页转发到 `/admin/404/`） |
| `/admin/`                                                | `pages/admin/index.astro`（后台仪表盘）                                                 |
| `/admin/posts/list/`                                     | `pages/admin/posts/list.astro`（文章列表）                                              |
| `/admin/posts/edit/?path=...`                            | `pages/admin/posts/edit.astro`（编辑器）                                                |
| `/admin/categories/`                                     | `pages/admin/categories.astro`（分类管理）                                              |
| `/admin/404/`                                            | `pages/admin/404.astro`（后台 404，前台 404 的转发目标）                                |

后台子页一律直接用 `xxx.astro` 文件当路由，不单开「文件夹 + index.astro」；`/admin/`、`/admin/posts/` 这类纯前缀不放页面。`admin/_admin/` 是后台本体（布局 / 组件 / 样式 / 脚本），下划线目录不被 Astro 路由——后台自包含在这里，不 import 前台任何 `src/components/` / `src/layouts/` / `src/assets/`（需要相同的东西就拷进来各自维护；共享的只有构建期配置 `src/data/`）。

`about.astro` 用 `import { Content } from '../content/about.md'` 直接当组件渲染，不走 posts 集合。

## 布局与插槽

**`BaseLayout.astro`** —— 全站外壳：背景（`<Background />` 渲染 `div.bg`，方案由 `src/data/background.ts` 决定；时间轴两端渐隐层里还有一份同样类的 `.bg--clone` 克隆，用来跟任意背景方案对齐，见 `CSS.md` 的容器表）、`NavBar`、主内容行 `.page-main`（全站宽度的唯一执行点，见 CSS.md）、`Footer`、侧边按钮列、灯箱/图片占位的模板节点，以及一批 `<script>`。

- `<slot />` 主内容；`<slot name="head" />` 往 `<head>` 塞东西。`<head>` 里固定输出一条 `rel="alternate"` 的 RSS 自动发现链接，指向 `/posts/rss.xml`，阅读器据此找到订阅源；另有一条 `rel="canonical"`（`site.url` + 当前路径），让搜索引擎以站点域名的绝对路径为准。
- **首载 loading 屏 `#boot-splash`**（仅前台；后台走 `AdminLayout`，没有）：body 第一个元素 + head 里自足的 `<style is:inline>` 样式块 + head 顶部给 `html` 加 `js` 类的 `<script is:inline>`（门：无 JS 不显示，避免整屏盖死）+ body 尾部淡出脚本（等 `window load` 才揭幕——CSS 背景图、首屏图片、脚本包全就绪，揭开后第一帧即加载完整的页面；脚本执行时文档已 `complete` 则立即揭幕；`load` 后再等一帧 rAF，保证揭幕画在已绘制的一帧上；隐藏标签页 rAF 不跑，该状态下改挂 200ms 计时兜底，渐隐不拖到切回标签页，见 `TROUBLESHOOTING.md` 第 68 条；揭幕时进度条先 0.5s 过渡滑满、走完后整屏才 0.5s 渐隐（减动效下条形不画、直接渐隐）；进度条与最少 200ms 展示的时钟零点在**首个 rAF 帧**（用户第一次看见屏幕），按脚本执行时刻量的话主线程卡顿下首帧已 57%–92%、条形「直接就在最后面」，见第 67 条；减动效下 rAF 不跑、零点回落脚本执行时刻；5s 超时兜底——个别资源卡死时遮罩不永久盖住页面）。背景图经 `Image` 预热走缓存、就绪后给 `.bg--image` 加 `.is-ready` 自行 0.8s 淡入（见 `CSS.md`）；`load` 本身会等 CSS 背景图，揭幕时图已就位，兜底超时路径（图未就绪）下背景图到位后自行淡入，也不 pop。只在首次加载出现：swup 切页只换 `#swup`、不重建 body 壳，节点也已在首次加载后被移除。类明细见 `CSS.md`「首载 loading 屏」。
- `.page-main` 行 = 常驻侧边栏 `GlobalSidebar` + `main#swup`（swup 的替换容器）。侧栏在 `#swup` **之外**、渲染在**每一个**站点页的壳里（普通页隐藏、文章区显示）：swup 只换 `#swup` 内容，所以文章区界面之间切换时侧栏永不重建——分类树手动开合的状态保留、不闪。行里另有两件 `main#swup` 之外的常驻件：搜索浮层 `.posts-search-float`（真实搜索框，`posts/search-float.ts` 摆位）与左缘常驻盒 `.posts-edge-float`（文章区左缘条——页头 / 面包屑——的显示实例，`posts/edge-float.ts` 把 `#swup` 内的驱动条深克隆换入盒内车道）；两者切页同样永不重建。
- `shellVariant` prop（`plain` / `listing` / `post`）决定行的变体类首帧（侧栏显隐）；swup 切页后由 `posts-shell.ts` 按内容标记（`.posts-page` / `.post-content`）重新同步。
- **放进 `main#swup` 的 Svelte 岛在切页时会被重新插入 DOM**，这决定了水合指令的选择（见 `docs/rules/40-astro-svelte.md`）。

**`PostsShell.astro`** —— 文章区统一布局（继承 `BaseLayout`），列表 / 分类 / 标签 / 文章详情四种路由共用（常驻侧栏在 `BaseLayout` 壳里，不在这个组件里）：

- `variant="listing"`（列表 / 分类 / 标签）：`.posts-header` 页头（标题 + 计数 + 搜索占位 `.posts-header-search`——真实搜索框是 BaseLayout 行级常驻的 `.posts-search-float`，占位只留布局空间、`posts-shell.ts` 把常驻搜索叠上来）+ `.posts-grid` 卡片栅格 + 空状态。页头带 `data-posts-anchor`，是侧栏顶偏移的测量锚；**≥769px 页头用负边距通栏压过侧栏区、顶到行左缘**（侧栏在页头下方开始，作者卡顶对齐栅格顶）。桌面端页头高精确等于面包屑条（36px，标题 `line-height: 1` 仅 25.6px），与文章页的面包屑条构成「同位同高」的左缘元素对（两者内容顶都在 132px、侧栏偏移同 50px，切页零位移；等高约束见 `CSS.md` 的「文章列表」节）。页头与面包屑的显示实例都在行级常驻盒 `.posts-edge-float`（见 `.page-main` 行那条）：布局里的驱动条本体只当布局锚与无 JS 回退，显示实例是盒内车道的深克隆——跨区切页常驻盒随全局曲线位移，区内切页盒不位移、车道等新页落地才变（旧车道渐模糊 → 播完换入克隆 → 去模糊）。
- `variant="post"`（文章详情）：`.posts-article` 行两列——左列 `.posts-article-main`（`.posts-breadcrumb` 面包屑条 + 正文卡，gap 桌面 14px / 手机 13px；手机端面包屑条（28px）在「导航底→正文卡顶」54px 空窗内垂直居中：70 + 28 + 13，正文卡顶 111 与列表页搜索框顶 110.6 对齐）与右侧 `.post-sidebar`。面包屑条同样带 `data-posts-anchor`；≥1151px 用负边距向左压过侧栏区、与侧栏顶边同一水平线，≤1150px 侧栏隐藏时就是卡片正上方。正文卡 `article.glass`，正常文章带 `data-pagefind-body`；**目录顶到行顶**（与面包屑条 / 侧栏顶同一水平线，sticky top 82px 夹持，≤850px 隐藏）。面包屑的显示实例同样在 `.posts-edge-float`（与列表变体页头共用同一常驻盒，见前一条）。
- 默认 `<slot />` 是正文；`<slot name="postnav" />` 上一篇/下一篇；`<slot name="comments" />` 评论区。
- 传 `hidden` 时正文卡**不输出** `data-pagefind-body`，并由 `BaseLayout` 输出 `noindex`——这是隐藏文章不进搜索与搜索引擎的两个开关。

> 搜索索引只含文章页：构建时 `astro.config.ts` 的 `pagefindArticles()` 只把未隐藏文章的产物喂给 Pagefind，命中内容再由 `data-pagefind-body` 限定在**文章正文**；分类 / 列表 / 标签页不进索引，隐藏文章在构建期就不进索引。

**`AdminLayout.astro`** —— 后台独立外壳，**不继承 `BaseLayout`**（后台不要全站导航与页脚），自己输出整份 `<html>`/`<head>`/`<body>`，只引入 `src/pages/admin/_admin/css/` 下三个文件：`base.css`（重置 / 文字链接 / swup 进度条 / 滚动条拖拽态，经 `@import` 引 `variables.css`）、`elements.css` 元件、`admin.css` 布局；令牌全在 `_admin/css/variables.css`（蓝白商业风独立一套，与前台零共用零拷贝），不 import 前台任何 `src/assets/css/`，也没有磨砂与背景容器（页面底色是平铺的 `--page-bg`）；删后台时连 `_admin/` 目录一起删。

- 结构是「顶栏 + 侧栏 + `main#swup`」，其中 `AdminToken`（连接面板）与 `AdminNav`（侧栏）放在 `main#swup` **之外**，`AdminChanges` 也挂在容器外：swup 只替换 `#swup` 里的内容，所以切页时连接状态、填到一半的密钥与待提交队列都不会消失。
- 切页有整块 CSS 转场（`#swup` 的 `.transition-page`，见 `global.css`「切页转场」；后台自身无动画，`_admin/css/base.css` 用 0.01s 占位动画满足 swup 的等待目标），加载反馈是顶部细进度条（`progress` 插件）。顶栏在 `main#swup` 之外、切页不动；行级侧栏与搜索框虽在 `#swup` 外，按行变体类参与同一组转场动画（见 `global.css`「切页转场」）。动切页路径前先读 `docs/reference/TROUBLESHOOTING.md` 第 20 条的两个长期约束（backdrop root / animationSelector）。
- 后台页统一 `noindex`，且不输出 `data-pagefind-body`（不进 Pagefind 索引）；`public/robots.txt` 里 `Disallow: /admin/`。
- 站点页与后台页的外壳不同，跨过去必须整页加载。出口分两条：点击路径——后台「回到站点」链接（`AdminNav` 里）带静态 `data-no-swup`，swup 把这次点击交给浏览器整页加载；前进/后退路径——swup 同样接管前进/后退，而 `ignoreVisit` 只作用于点击，所以由 `shell-guard.ts` 监听 `popstate`（前台 `src/assets/js/nav/shell-guard.ts`、后台拷贝 `src/pages/admin/_admin/js/shell-guard.ts`，两个外壳各 import 自己那份），发现「当前外壳」与「目标 URL」对不上就掐掉 swup 的处理并整页 reload，`swup:content:replace` 上再兜一层 reload。

## 客户端运行时

### swup 生命周期事件

站点用 `@swup/astro` 做无刷新切页。库会把 swup 的 hook 以 DOM 事件派发到 `document`：

| 事件                                    | 时机              |
| --------------------------------------- | ----------------- |
| `swup:visit:start`                      | 开始跳转          |
| `swup:content:replace`                  | 新内容已插入 DOM  |
| `swup:visit:end`                        | 本次跳转结束      |
| `swup:scroll:start` / `swup:scroll:end` | 滚动复位前后      |
| `swup:any`                              | 任意 hook，调试用 |

同时 `@swup/astro` 会派发 Astro 风格别名：`astro:before-swap`（对应 `content:replace` 之前）、`astro:after-swap`（替换瞬间）、`astro:page-load`（对应 `page:view`，转场结束）。注意这三个事件都由 `document.dispatchEvent(new Event(name))` 派发、**不冒泡**（`new Event` 默认 `bubbles: false`），监听必须挂在 `document` 上（挂 `window` 收不到，见 `TROUBLESHOOTING.md` 第 5 条）。

注意 `astro:after-swap` 是在 `content:replace` 这个时机派发的，而配置里 `SwupHeadPlugin` 开了 `awaitAssets`，会在替换内容前等新样式表加载好，避免样式闪烁；同时开了 `persistAssets`，旧页面样式在内容真正被替换前不从 head 移除，过渡期间旧内容不掉样式（原理见 `TROUBLESHOOTING.md` 第 24 条）。

顶部进度条是官方 `@swup/progress-plugin`（`astro.config.ts` 的 `progress: true` 启用），动态插入自己的元素与默认样式、没有自定义脚本；高度与颜色在 `global.css` 覆盖（`body .swup-progress-bar`）。

**事件族约定**：站点脚本统一监听 `swup:content:replace`（新内容已插入 DOM），不要用 `astro:after-swap`——后者是 `@swup/astro` 的别名、与 `content:replace` 同一时机，两族混用时模块间的先后关系只存在于「目前碰巧是对的」这一事实里。

`swup:content:replace` 的 `event.detail.visit` 是 swup 的公开访问对象，`visit.trigger.el` 是「触发这次换页的链接」——`nav/nav-indicator.ts` 用它判断「这次换页对应哪次点击」，不依赖 swup 的内部状态编号（内部编号属于私有实现，升级无兼容承诺）。

### 动画依赖：motion

汉堡菜单开合与导航下划线位移由 `motion` 的 **vanilla（框架无关）API** 驱动（`animate()`，底层是 WAAPI）。它不是框架：没有 `<Motion>` 组件、没有 React/Svelte 适配器——`@motionone/svelte` 是坏包且只支持 Svelte 3（见 `TROUBLESHOOTING.md` 第 28 条）。消费方脚本：`nav/hamburger.ts`（移动端）/ `nav/nav-indicator.ts`（桌面端）由 NavBar 动态 import、按设备互斥；`posts/posts-shell.ts` 在首帧后空闲预取（`preloadMotion()`，首屏不拉共享块，点击前基本就绪）；`posts/category-tree.ts` 由 `posts/posts-shell.ts` 懒加载（普通页侧栏隐藏、树无交互时不加载）。切页转场是纯 CSS（`global.css`「切页转场」），不走 motion。全站「开窗露内容」的展开/收起由 `util/expand-collapse.ts` 统一编排（窗口与刚体同曲线同长；`posts/category-tree.ts` / `nav/hamburger.ts` 走这里，首帧后空闲预取 motion，见下脚本职责表；后台外壳用自己的拷贝 `admin/_admin/js/expand-collapse.ts` 编排侧栏二级菜单）。motion 共享 chunk 约 19.6 kB gzip，首帧后空闲预取（交互先于预取发生时 `animateLazy` 直接落终态，不等待）。

**选型原则：新增 JS 驱动的动画（状态变化补间）一律优先 motion 的 vanilla API**——不手写 rAF tween、不引其他动画库（硬约束见 `00-project.md`）。例外只有三类：

- `toc.ts` 共用过渡：单条进度 p 同驱动竖线与轨道两条通道、每帧从当前位置重定向——是「连续过程」不是离散补间，motion 的 tween 模型在快速重定向下有写入竞态（见 `TROUBLESHOOTING.md` 第 30 条 ②）。
- 输入跟随（值 → 几何 1:1、无缓动曲线）：`scrollbar.ts` 拖动、`swup-widgets.ts` 进度环——rAF 只做写入合并，不算动画。
- 悬停反馈、骨架屏、背景动效、抽屉开合等两态装饰：纯 CSS，不走 motion。

motion 用法守两条约定：

- CSS 只写**两个端点状态**（`.is-open` / 基础态）的静态值，不写 `transition` / `animation`；动画终值必须与 CSS 端点一致（motion 结束时会把最终关键帧写进内联样式，优先级高于类）。
- 中断续接时**先读 `getComputedStyle` 的飞行中值、再翻类**（翻类后 computed 变成端点值，飞行位置丢失）；瞬移 = `cancel()` 全部 controls + 翻类（详见 `TROUBLESHOOTING.md` 第 29 条）。

### 后台的数据流

```
AdminToken 表单（owner/repo/branch/token）
        │  shell.ts 校验：GET /user + GET /repos/{owner}/{repo}
        ▼
adminStore（模块级单例，只活在内存里）
        │  pages.ts 读仓库 → 列出 / 读取 src/content/posts/**/*.md
        ▼
编辑器改内容 → adminStore.stage(path, content, original)   暂存队列（可跨页累积）
        │  AdminChanges 面板点「提交」
        ▼
admin/_admin/js/github.ts commitStaged()
  取分支头 sha → 取头提交的 tree → 逐个变更建 blob → 建 tree（带 base_tree）
        → 建 commit（parents: [headSha]）→ PATCH 分支引用（force: false）
        ▼
        一个提交包含全部改动
```

要点：

- **提交是「一次性打包」**，不是每个文件一次 PUT。N 个改动只产生一个 commit、一次站点构建。
- tree 带 `base_tree`，所以只需要上传「有改动的路径」，其余文件由 GitHub 沿用基准 tree。删除的路径把 `sha` 传 `null`。
- 更新分支引用时 `force: false`：这期间有人推了新提交会返回 409，不会把别人的改动顶掉。
- 中文内容用 `TextEncoder`/`TextDecoder` 走 base64，避免 `btoa` 的 Latin-1 限制导致乱码。
- 提交期间 `adminStore.committing` 为真，暂存与撤销被拒绝，避免提交快照与队列不一致。

## 构建流水线

`astro.config.ts` 的集成按顺序执行，其中几个和产物正确性强相关：

| 集成 / 钩子           | 作用                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | 不能动的地方                                                                                                                                                                                               |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pagefindArticles()`  | 构建钩子：只把未隐藏文章页的产物喂给 Pagefind，生成搜索索引；dev 下无索引                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | 新增文章后要重新 `build` 才能搜到；注册位置必须在 `pruneUnusedAssets()` 之前（prune 负责删 `dist/pagefind/` 里的官方 UI 包）                                                                               |
| `swup({...})`         | 无刷新切页、head 更新（`awaitAssets` + `persistAssets`）、顶部进度条（`progress`）、切页转场等待（`animationClass: 'transition-'`：唯一等待目标是 `#swup` 的 `.transition-page`，swup 按其 `animationDuration` 等退出播完才替换 DOM、等进入播完才收尾，令牌 `--t-page-exit` / `--t-page-enter`；后台用 0.01s 占位动画消警告，见 `src/pages/admin/_admin/css/base.css`；机制见 `global.css`「切页转场」与 `TROUBLESHOOTING.md` 第 20 / 37 条）、`globalInstance: true`（`window.swup` 供 `posts-shell.ts` 订阅 `fetch:error` / `visit:abort` 钩子——fetch 失败（404 / 中断）且仍留在列表系界面时兜底恢复搜索框；实例在 `load` + idle 才创建，首屏早期点区内链接由 `posts-shell.ts` 拦截等待后转 `navigate()`——见 `TROUBLESHOOTING.md` 第 47 条） | `containers` 必须和 `main#swup` 一致；`persistAssets` 必须保持 `true`，否则 head 换页时旧内容先丢样式（见 `TROUBLESHOOTING.md` 第 24 条）                                                                  |
| `htmlMinifier({...})` | HTML 深度压缩，含内联 CSS/JS                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | `removeComments` 必须保持 `false`；保护 `astro-island` / `astro-slot` 的 `ignoreCustomFragments` 不能删，否则 `collapseWhitespace` 会删掉岛内空白节点导致水合 mismatch（见 `TROUBLESHOOTING.md` 第 26 条） |
| `stripSafeComments()` | 自定义钩子：删掉展示性 HTML 注释                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | 必须保留 Svelte 水合锚点与 Astro 岛屿标记                                                                                                                                                                  |
| `inlineCss()`         | 自定义钩子：把 head 里的 `<link rel="stylesheet">` 内联成 `<style>`——外链 CSS 是渲染阻塞资源，内联后首帧不阻塞在 CSS 下载上，`#boot-splash`（首载 loading 屏）随第一块 HTML 就画出                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | 必须在 `stripSafeComments` 之后运行（读的是最终 HTML）；`awaitAssets` 只等 `link[rel=stylesheet]`，内联后 swup 切页无等待、不闪样式                                                                        |
| `pruneUnusedAssets()` | 自定义钩子：删掉产物里没人请求的文件——已内联的 CSS 副本、Pagefind 官方 UI 包、只作为模块被引用而页面实际用优化变体的图片原图                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | 必须在 `inlineCss` 之后运行（内联后才知道哪些 CSS 成了副本）；**只删 CSS 与图片，不碰 JS 分块**——动态 import 的分块名在产物里的形式不唯一，误删会直接让页面功能失效                                        |

两个自定义钩子各带一组构建期自检，不达标直接让构建失败（报错里给出页面路径与残留标记）：

| 自检                | 断言什么                                                                                  | 为什么不会误报                                                         |
| ------------------- | ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `stripSafeComments` | 删注释前后，水合锚点数与 `<astro-island>` 数必须相等                                      | 两边用同一个检测器——Astro 换锚点格式时两边一起变 0；真被删掉才是 N → 0 |
| `inlineCss`         | 内联后扫外链 stylesheet，必须一条不剩（探测器故意比替换正则宽：不认属性顺序与自闭合写法） | 探测范围宽于替换范围，替换正则漏匹配时它才抓得到                       |
| 两者                | 至少处理到一个 HTML 文件                                                                  | 只有下界，防 `outDir` 解析错时空转仍报成功                             |

**只写恒等式，不写绝对数量**：锚点 179、岛屿 101 这类数字会随页面增长而过时，写进断言就变成「代码合法改动却构建失败」的假失败。

## 缓存

| 位置                       | 缓存什么                                | 失效方式                                              |
| -------------------------- | --------------------------------------- | ----------------------------------------------------- |
| `lib/posts-data.ts`        | 整个 `BlogData`（模块级 Promise 缓存）  | 进程结束即失效；dev 下内容变更由 Astro 内容层触发重建 |
| `assets/js/data/github.ts` | GitHub 仓库列表与数量（`localStorage`） | `data/github.ts` 的 `cacheTTL`（默认 1 小时）         |
| swup                       | 已访问页面的 HTML                       | 配置里 `cache: true`；dev 调试可临时关掉              |

后台**没有任何持久缓存**：`admin/_admin/js/store.ts` 是内存单例，整页刷新即清空。这是有意为之——密钥不进浏览器存储，交给浏览器的密码管理器按登录表单（`autocomplete="username"` / `current-password`）保存。
