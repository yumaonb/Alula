# 内容体系

写文章只需要关心两件事：**放哪个目录** 和 **frontmatter 填什么**。

---

## 目录即分类

`src/content/posts/` 下的目录层级就是分类层级，没有第二个分类来源。

```
src/content/posts/
├── alula/                      分类 alula（有 index.json）
│   ├── index.json
│   └── posts/
│       ├── index.json
│       ├── categories.md       文章 alula/posts/categories
│       └── fields.md
└── devnotes/
    ├── index.json
    ├── css/
    │   ├── index.json
    │   ├── at-rule.md          文章 devnotes/css/at-rule
    │   └── ...                 其余 CSS 速查文章
    └── shell/
        ├── index.json
        └── shell.md
```

- 目录名用英文小写，不要空格；显示名走 `index.json`。
- 分类页会**自动生成**：只要目录里有文章或有 `index.json`，`/posts/<该目录路径>/` 就存在。中间层级（如 `devnotes`）即使自己没有文章，也会因为子目录而生成分类页。
- 侧栏分类树、面包屑、标签云全部由数据自动推出来，不需要改组件。

### `index.json`

放分类的显示信息，可选但强烈建议：

```json
{
  "name": "开发速查",
  "description": "前端基础知识速查表"
}
```

| 字段          | 说明                                               |
| ------------- | -------------------------------------------------- |
| `name`        | 导航、面包屑、分类页标题显示的名字；不填就用目录名 |
| `description` | 分类描述，目前用于元数据预留                       |

---

## frontmatter

| 字段          | 类型     | 默认    | 说明                                                                                                                                                                       |
| ------------- | -------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `title`       | string   | 无标题  | 卡片与页面标题                                                                                                                                                             |
| `date`        | 日期     | 必填    | 决定排序（倒序）。日期写 ISO 格式 `2026-09-06`：`2026-9-6` 这类非 ISO 写法按**本地时间**解析，与 ISO 的 UTC 解析差一个时区。`content.config.ts` 里是必填，缺了构建直接失败 |
| `description` | string   | 空      | 卡片摘要 + `<meta name="description">`                                                                                                                                     |
| `image`       | string   | 空      | 封面图，相对本文的路径                                                                                                                                                     |
| `tags`        | string[] | `[]`    | 标签，决定标签页与侧栏标签云                                                                                                                                               |
| `pinned`      | boolean  | `false` | 置顶；置顶优先于日期                                                                                                                                                       |
| `hidden`      | boolean  | `false` | 隐藏文章，见下节                                                                                                                                                           |

```markdown
---
title: Flexbox 完全指南
date: 2026-08-20
description: 主轴、交叉轴、换行与对齐的完整梳理
image: ./images/flexbox.png
tags: [CSS, 布局]
pinned: false
hidden: false
---

正文……
```

> **`categories` / `category` / `分类` 字段会被忽略。** 分类只由目录决定，写了也不生效。

---

## 隐藏文章

`hidden: true` 的文章**只保留"能通过链接打开"这一件事**，其余出口全部关掉：

| 出口                               | 隐藏文章                                                |
| ---------------------------------- | ------------------------------------------------------- |
| 文章列表 `/posts/`、分类页、标签页 | 不出现（计数也不含它）                                  |
| 侧栏分类树、标签云                 | 不统计它（只有隐藏文章的分类不会凭空冒出来）            |
| 其它文章页的上一篇 / 下一篇        | 不出现（隐藏文章自己的页面也没有导航）                  |
| RSS `/posts/rss.xml`               | 不收录                                                  |
| 站内搜索（Pagefind）               | 不索引（页面不输出 `data-pagefind-body`）               |
| 搜索引擎                           | 页面带 `<meta name="robots" content="noindex, follow">` |
| 直链 `/posts/<分类>/<文件名>/`     | **正常访问**，正文、目录、评论都在                      |

```markdown
---
title: 只有我自己知道的一篇
date: 2026-09-18
hidden: true
---

正文……
```

几条口径：

- 隐藏文章仍然**占用路由**，所以它所在的分类页（含中间层级）一定会生成，哪怕那个分类下没有别的文章。
- 隐藏与置顶互不影响：`hidden: true` 优先，置顶也不会让它出现在列表里。
- 它是"不公开"，不是"不发布"：产物里有这个 HTML 文件，知道 URL 的人就能看。要真正保密就别提交进仓库。
- 想让整篇彻底消失，删文件比设 `hidden` 干净；`hidden` 的用途是"留个只有我有链接的页面"。

## 排序与展示口径

| 项     | 规则                                                                                                                                                                                             |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 排序   | 置顶优先，然后按 `date` 倒序                                                                                                                                                                     |
| 字数   | 中文按字符数、英文按单词数，去掉代码块与图片链接后估算，用于卡片上的"字数"                                                                                                                       |
| URL    | `/posts/<分类目录路径>/<文件名>/`，根目录文章为 `/posts/<文件名>/`                                                                                                                               |
| 订阅源 | `/posts/rss.xml` 把全部文章按同样的顺序输出：**全文**（`content:encoded`，与文章页同一条 markdown 管线）、标签、作者，发布时间用这里的显示日期；文章有 `image` 封面时额外输出 `enclosure` 缩略图 |

### 评论与 URL 的绑定关系

giscus 按 **pathname** 映射讨论，讨论标题就是"去掉前导斜杠的页面路径"（例如 `posts/devnotes/css/at-rule`）。

**所以文章一旦发布就不要改文件名或挪目录**，否则原有评论会失联（见 `TROUBLESHOOTING.md` 第 9 条）。

## 图片

三种情况要分清：

| 写法                              | 结果                                                                                    |
| --------------------------------- | --------------------------------------------------------------------------------------- |
| `./images/x.jpg`（相对本文）      | 由 `ImageWrapper.astro` 依据文章的 `basePath` 解析，走 Astro 图片优化，输出到 `_astro/` |
| `https://...`（外链）             | 原样输出成 `<img>`，不优化                                                              |
| `/images/x.jpg`（站点根绝对路径） | 也能显示，但**绕过优化**，通常不该这么写                                                |

约定：

- 图片放文章同级目录的 `images/`，和文章一起走版本库。
- 不要在 `images/` 里放其他文章要用的图；跨文章共用就放 `src/assets/images/`。
- 封面图（frontmatter 的 `image`）和正文图走的是同一套解析，都能用相对路径。

## 新增文章流程

1. 确定分类：先看 `src/content/posts/` 现有目录，能挂到已有的就不新建。
2. 新分类建目录 + `index.json`（填 `name`，不填就退回目录名）。
3. 新建 `<文件名>.md`（英文小写加连字符，文件名即 URL 尾段），写 frontmatter 与正文；不要写 `categories` 字段。
4. 需要图片就建同级 `images/` 放图，正文用相对路径引用。
5. 想写「只有直链能打开」的文章就设 `hidden: true`（判据：这篇要不要出现在任何列表里，见「隐藏文章」节）。
6. `pnpm format` → `pnpm verify` → `pnpm build`，确认 `dist/posts/<分类>/<文件名>/index.html` 生成、正文有内容，且页面数比改动前多 1（新分类再多 1）。

核对清单：

```
- [ ] 分类目录已存在，或已新建 index.json 并填了 name
- [ ] frontmatter 没有 categories / category 字段
- [ ] 图片在同级 images/ 且用相对路径引用
- [ ] 该隐藏的加了 hidden: true，并在构建产物里确认它没出现在列表 / RSS / 搜索里
- [ ] pnpm verify 全过、pnpm build 成功，页面数比改动前多 1
```

> 两个容易踩的：
>
> - 中文标签支持，但标签名大小写敏感：`#css` 和 `#CSS` 是两个标签，保持前后一致。
> - 新文章在 `pnpm dev` 下搜不到属正常，Pagefind 索引来自上次 `pnpm build` 的 `dist/`。
