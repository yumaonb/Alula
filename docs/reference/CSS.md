# CSS

本文只讲**机制与规则**（样式放哪、令牌语义、为什么这么写）；**类名清单**在 `docs/REGISTRY.md`（机器生成，`pnpm registry:write` 重建），本文不逐条登记。

## CSS 文件结构

| 文件            | 职责                                                                                                                                                                                                                                                                                                                     |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `variables.css` | CSS 变量定义（**只放全站都在用的**；后台专属令牌在 `admin/variables.css`）                                                                                                                                                                                                                                               |
| `global.css`    | 重置 + 页面基础结构（含全站背景容器 `.bg`），引入 `variables` / `utilities`                                                                                                                                                                                                                                              |
| `backgrounds/`  | 全站背景方案预设（`css/` 纯 CSS 绘制、`images/` 图片），由 `src/data/background.ts` 选择，见下文                                                                                                                                                                                                                         |
| `utilities.css` | 可复用的**元件级**类（玻璃拟态、悬停、页面标题等），**前台后台共用的元件放这里**；页面内容排版（描述/座右铭）不在这，写各页或页面组共享文件；页面结构（`.page`/`.page-main`）在 `global.css`                                                                                                                             |
| `shared/`       | **全站可复用的组件级样式**（比较大的、能划成"组件"的文件）：`skeleton.css`（骨架屏加载动画）+ `lightbox.css`（PhotoSwipe 灯箱主题微调，随 `lightbox-core.ts` 懒加载）+ `drawer.css`（右侧抽屉骨架，`PostsDrawers` 里两个抽屉共用）。卡片/按钮这类小元件不在这，在根目录的 `utilities.css` 聚合文件里                     |
| `admin/`        | **后台全部样式**：`variables.css`（后台令牌 `--nav-*` / `--admin-shadow*`，与根目录 `variables.css` 同名同职责、只服务后台）+ `admin.css`（布局）+ `elements.css`（`.card` / `.btn` / `.input` / 行列表 / 文件列表 / 徽标）。整个目录**只由 `AdminLayout` 引入**，不进站点其他页面；不想要后台时删掉目录即可，前台零依赖 |
| `posts/`        | **文章相关样式**：`posts-listing.css`（列表/分类/标签页共享布局，由 `PostsShell` 引入）+ `markdown.css`（正文 Markdown 排版，about 页也经 `Markdown.astro` 用）。文章详情页的行内样式（正文卡、右侧目录、面包屑条）在 `PostsShell.astro` 的 `<style>` 里                                                                 |

> 目录约定：css 根目录只放全站基础文件（`variables` / `global`）和**小元件聚合文件**（`utilities`，卡片/按钮这类）；**全站可复用的组件级大文件**（骨架屏/灯箱/抽屉这类）放 `shared/`；按功能归组的放对应文件夹（`posts/` 文章、`admin/` 后台）。

> 全局样式文件由页面或布局 import（例如 `BaseLayout` 引入 `global.css`、`shared/skeleton.css`、`shared/image-fallback.css`；`PostsShell` 额外引入 `posts/posts-listing.css`，文章详情页额外引入 `posts/markdown.css`）。背景预设**不在**这里 import，由 `virtual:background` 虚拟模块按 `src/data/background.ts` 的选择引入。

> **不许打开 CSS 压缩**：`astro.config.ts` 里 `compress()` 的 `CSS` 必须保持 `false`，否则 lightningcss 会删掉不带前缀的 `backdrop-filter`，全站玻璃模糊失效。原因见 [TROUBLESHOOTING.md](./TROUBLESHOOTING.md#1-全站毛玻璃模糊失效firefox-尤其明显)。

> `public/css/giscus.css` 是 giscus 评论组件的主题：上传静态托管后由 `data-theme` 的 URL 引用，**不进站点构建产物**。站点样式表到不了 giscus 的 iframe，覆盖第三方默认样式只能靠它自己的 `!important`，属必要豁免，不受「不用 `!important`」约束。

新增**全站**变量写在 `variables.css` 的 `:root` 里；后台专属令牌（`--nav-*` 侧栏 7 个 + `--admin-shadow*` 投影 2 个）写在 `admin/variables.css` 的 `:root` 里，随后台一起进退。

文章区局部变量（`--posts-side-w` / `--posts-side-gap` / `--posts-offset-gap` / `--posts-side-offset`）定义在 `global.css` 的 `.page-main` 上（只有文章区行读它们），不进 `variables.css`，作用见下方「全局宽度规则」。

**圆角两档，按元件角色判定（不看尺寸）**：`--radius`（10px）给卡片与按钮——文章卡 / 友链卡 / 赞助卡 / 技术栈面板 / 标签面板，以及重试、筛选这类按钮；`--radius-sm`（6px）给小标签 / chip——技术栈标签、文章卡标签、标签云 chip、项目主题标签，以及时间轴滚动区的聚焦圆角。不属于这两类的各自按语义取值，不套令牌：标题竖条 accent、分类树项 / 目录项、行内代码、骨架占位条、圆形头像（50%）、完整胶囊（999px）。

**过渡时长原则上不做令牌**：动画时长按各处观感直接写死（位移 / 开合 / 显隐 / 图片缩放等，`0.18s` / `0.3s ease` / `0.34s cubic-bezier(...)` 等），不收敛、不统一。**唯一例外是悬停提亮**：「鼠标移入 → 提亮 / 淡入」的过渡时长统一令牌化为 `--t-hover`（见上表）——这一类悬停变过去一律写 `var(--t-hover)`，全站同一速度、渐变过去而不是跳变；同一规则里共用的 `:focus-visible` 随之同行，纯聚焦触发的反馈（输入框描边等）仍各自定。唯一要守的是媒体查询断点仍按规则第 5 条走。

**磨砂统一挂 `.glass` 类**：全站磨砂效果只在 `utilities.css` 的 `.glass` 里定义一次（透明底 + `backdrop-filter` 取 `--blur` + 1px 内描边 + 统一投影），玻璃卡、悬浮小按钮、搜索胶囊 / 下拉、抽屉、滚动条、后台按钮 / 卡片 / 侧栏都用它；组件与页面样式**不再自己写 `backdrop-filter`**，也不要硬编码模糊半径。想统一加浓/减淡全站磨砂，只改 `--blur` 这一个值。`-webkit-` 前缀那行同样用变量，两行成对（`.glass` 里已写好一份）。

例外：`src/assets/backgrounds/css/*.css` 里的 `filter: blur(56px)` / `blur(72px)` 是给色斑柔化边缘用的**背景预设自身**参数（不是玻璃采样），按预设各自的观感取值，**不接入 `--blur`**。

**文字与图标同一套两级规则**：静止色统一 `--ink`（正文文字与常规图标同值，后台同样适用）；悬停/选中/激活态（图标和文字）走 `--white`；恒定全白的静止文字（标题、粗体、品牌名、后台标题与数值、输入框文字等）与无状态恒定全白图标（图上占位图标、卡片箭头）直接走 `--white`，压暗用各自的 `opacity` 表达。

**可点击的文字也用图标那套**：纯文字链接 / 文字按钮（自身反馈只有颜色变化的）静止走 `--ink`、悬停/选中走 `--white`——导航链接（桌面 + 手机端）、文章目录、分类项、标签 chip、正文 meta 链接、面包屑、转载来源链接等。卡片类元素（反馈是白底 + 描边，如文章卡片、上一篇/下一篇、友链卡片）内部的展示文字仍走 `--ink`，交互反馈由容器承担。原 0.45–0.9 的中间白值已全部收敛进上述规则。

**聚焦框标准**：`--hover-line` 是聚焦描边的唯一来源，后台 `.input` / 编辑器 / 变更停靠条输入框（聚焦时只把边框色提亮）与搜索容器 `:focus-within`（inset 描边）都用它。**不要在外圈再加光晕/第二圈描边**：边框 + 外圈叠在一起会像"两个输入框"（原 3px `--focus-halo` 已删除）。行列表同理：整行没有独立聚焦框，提示只给行内输入框自身。

**遮罩标准**：`--mask` 是页面级黑色遮罩的唯一来源（以手机端汉堡菜单遮罩为准），手机菜单、目录弹窗、筛选弹窗、后台抽屉、后台连接弹窗、卡片封面悬停遮罩（`.cover-overlay`）都走它。

**投影标准**：黑色投影全部走令牌，不许硬编码——`--shadow`（唯一抬升：玻璃卡片 / 前台弹窗 / 按钮 / 搜索胶囊，页标题文字阴影也走它）、`--admin-shadow` / `--admin-shadow-drawer`（后台提示条 / 手机侧栏抽屉，定义在 `admin/variables.css`）。新增投影先找这三个里最贴的，都不贴再按「新增 CSS 的规则」提新令牌。白色辉光类（头像光环、进度环、后台错误提示描边）不是投影体系，按各自语义留原地。

**按钮按下标准**：`:active` 按下反馈全站只有一条——`admin/elements.css` 的 `.btn:active:not(:disabled)`（背景硬编码 `rgba(255, 255, 255, 0.12)`）。前台按钮没有按下态；`--active-bg`（0.24）是**选中态**填底（chip / psd-item），别拿它当按下色。

**硬编码值白名单（例外）**：以下类别允许不走令牌、按文件内局部值写死，除此之外出现新的硬编码颜色先问一句「能不能并入现有令牌」：

1. **图上 / 装饰性极淡图标**：CC 徽标 0.05、图片占位图标的压暗 opacity（0.5 / 0.75）
2. **跟随文字的小图标（E 类）**：不写自己的 `color`，继承周围文字色再叠 `opacity` 0.55–0.8（面包屑 0.65、目录 0.55、meta 行 0.6 等），文字换令牌后自动跟着变
3. **机制文件（自成体系的观感值）**：骨架屏（0.06 / 0.14）、swup 进度条、首载 loading 屏（站点名 0.92 / 轨道 0.1 / 高光 0.85 + 兜底底色 `#000`）、时钟（独立仪表配色 0.15 / 0.55 / 0.7 + 自身黑投影）、自定义滚动条（0.45 / 0.7 / 0.9）、阅读进度环（轨道 0.08 / 进度 0.9）、头像光环（0.9 白环 + 0.25 白辉光，4 处各自持）
4. **markdown 正文局部排版值**（按规则留在 `posts/markdown.css`）：行内代码 0.08 / 0.1、引用 0.2 / 0.03、表格 0.1 / 0.06 / 0.03（行悬停）、hr 0.1、脚注 0.1、复选框 accent 0.6。**代码块的底色与正文色已令牌化**（`--astro-code-background` / `--astro-code-foreground`），不在此列
5. **单点局部值**：内容内小滚动条（目录 0.1、搜索下拉 0.15）、搜索 mark 高亮 0.18、赞助页分隔线 0.18、图片占位底 0.06（`shared/image-fallback.css` 的详情页封面 / 卡片封面 / 正文图占位 / 占位块四处）——单独出现、无共性，留原地
6. **后台的同值硬编码**：`admin/elements.css` 的 `.input` 圆角 6px、`AdminChanges.svelte` 的 6px / 9px 圆角——后台未引入 `--radius-sm` 令牌，先留原地

## 悬浮反馈（`--hover-*` + `.hoverable`）

**全站所有悬停效果只有一套**，底与边取自 `variables.css` 的 `--hover-bg` / `--hover-line`，文字/图标提亮色走 `--white`，提亮过渡时长走 `--t-hover`。
要实现悬停，给元素挂 `.hoverable` 即可，**不要在组件里再写 `:hover` 定颜色**：

```astro
<a class="friend-card glass hoverable" href="…">
  …
</a>{' '}
<!-- 玻璃卡片 -->
```

想整体调浓/调淡所有悬停反馈，只改 `variables.css` 里的 `--hover-bg` / `--hover-line`（提亮浓淡改 `--white`，提亮速度改 `--t-hover`）。

**hoverable 元素的静止态必须比悬停态更淡**：静止底必须比 `--hover-bg` 淡（写成同值，悬停白底就不可见）——标签用 `--rest-bg`（0.03）淡底即可，悬浮小按钮（back-to-widget）再挂 `.glass` 取磨砂，纯文字链接用 `transparent`；文字静止统一 `--ink`（0.88 白，悬停 / 选中提亮到 `--white`；两者相差 0.12，提亮偏柔和，想更明显就把 `--ink` 这一个值调低，如 0.75）；需要描边就用 `box-shadow: inset 0 0 0 1px var(--ring)`。踩坑实录见 [TROUBLESHOOTING](./TROUBLESHOOTING.md) 第 27 条。

**`.hoverable.hoverable` 为什么写两遍**：Astro 把组件 `<style>` 编译成 `.xxx[data-astro-cid-yyy]`，权重 (0,2,0) 且排在全局样式之后。只写一次 `.hoverable:hover`（也是 (0,2,0)）会被组件的静止态颜色盖掉，表现为「悬停没反应」。重复类名提到 (0,3,0) 才能稳定生效。**看到这行不要当成笔误去重**。

**挂 `.hoverable` 的元素不要再声明自己的 `transition`**：组件样式同样编译成 (0,2,0) 且排在全局样式之后，本地的 `transition` 会悄悄盖掉全站那份悬停过渡（background / box-shadow / border-color / color，时长 `var(--t-hover)`），悬停时颜色/描边直接跳变。确需过渡 transform 等额外属性，要么把共享的四个属性一并写全（时长同样走 `var(--t-hover)`），要么把过渡写到子元素上（如 PostCard 封面图缩放，位移时长各自定）。

例外（这些不是「按钮式反馈」，按各自语义取值、不挂 `.hoverable`）：正文表格行高亮、封面图缩放/遮罩、自定义滚动条滑块、只变文字色的正文链接（`.post-card-title-link` / `.post-card-category` / `.cat-item` / `.post-meta-link` / `.repost-url` / `.repost-license`，悬停色同样走 `--white`）、面包屑链接 `.breadcrumb-link`（只提亮文字、不加背景底——36px 细左缘条里挂 `.hoverable` 的悬停底色会多出一块底，观感突兀）、常规图标的悬停/选中/激活色（走 `--white`）。**这些例外的悬停提亮时长同样走 `var(--t-hover)`**——不挂 `.hoverable` 只意味着反馈形态不同（不加白底描边），「变过去」的速度全站统一；唯一的位移是封面图缩放（transform 各自定时长）。

## 全站链接与 `.link-plain`

`global.css` 默认给所有 `<a>` 统一的纯文字链接样式（`a:not(.link-plain)` 负责颜色与过渡）：静止与正文同色（`--ink`）、下划线默认显示（1px、`text-underline-offset: 2px`、颜色取 `currentColor` 与文字同步）；悬停 / 聚焦时文字提亮到 `--white`，下划线 `var(--t-hover)` 淡出，不直接跳变。纯 CSS 两条规则，无 JS 无额外节点。后台「最新提交编号」链接（等宽字体）同样走这条规则。

自带样式的链接——按钮、卡片、导航项、标签、目录项、后台链接、只变文字色的正文链接——在标记里挂 **`.link-plain`** 退出这套效果：

```astro
<a class="friend-card glass hoverable link-plain" href="...">
  …
</a>
```

- `.link-plain` 是**纯标记类**，本身不产生任何样式，只供 `global.css` 的选择器排除。
- 要下划线样式就不挂它；要退出就挂它——**不要**再去 `global.css` 里追加 `:not(.xxx)`，那会把选择器权重堆高，连组件自己的 `padding` / `display` 都可能被压掉。
- 正文链接由 markdown 渲染、加不上类名，直接沿用上面的全站链接样式，`posts/markdown.css` 不单独定义 `a`。

## 玻璃拟态与白纱

| 类名          | 用途                                                                                                                                                                                                                                              | 示例                                              |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| `.glass`      | 全站磨砂效果**唯一定义**：透明底 + 磨砂（`backdrop-filter` 取 `--blur`）+ 1px 内描边 + 统一投影 `--shadow`；凡需要磨砂观感的元素都挂它                                                                                                            | `<div class="glass">`                             |
| `.glass-tall` | 超高容器（内容可能超过手机 GPU 纹理上限约 4096px）的磨砂回退：容器自身不模糊，改由一屏高（100vh）的 `sticky` `::before` 承担；不支持 `overflow: clip` 的浏览器自动退回容器直接模糊。容器自身不设 padding、不自己滚动，见 `utilities.css` 里的注释 | `<article class="post-content glass glass-tall">` |

背后是固定背景（`.bg`）还是页面内容（固定顶栏盖住滚动内容、后台顶栏 / 弹窗 / 停靠条悬浮在内容上），都直接挂 `.glass`，`backdrop-filter` 实时采样绘制在背后的像素。超高卡片追加 `.glass-tall`。磨砂观感强弱取决于背景预设的高频细节，见「全站背景」节的「高频细节是磨砂感的前提」。

**白纱规则（移动渐隐的毛玻璃通用，用户定的规矩）**：磨砂元素（背景全透明、观感全靠 backdrop 模糊）在**渐隐**时，模糊会随元素透明度一起淡掉——「磨砂感突然变透明」，观感生硬。**所有需要渐隐的毛玻璃移动动画都必须**：位移/淡出的同时，把元素背景在 `透明 ↔ --glass-veil`（半透明白纱）之间过渡——白纱渐浓、模糊渐退，实体白接替磨砂再整体消失。**渐显也铺白纱**：入场动画启动的**同任务里**先把容器背景 pre-pin 到 `--glass-veil`（之间无绘制间隙，不会单独闪一帧白条），关键帧再随入场全程褪回透明——「白纱褪去、玻璃浮现」，与渐隐对称（用户指定：入场渐显那会儿要在入场前加上半透明白）。目前唯一执行者是搜索胶囊的转场（`posts-shell.ts` 驱动）：白纱写在**容器** `.posts-search-float`（`border-radius: 999px` 与胶囊同盒对齐）而不是胶囊上——胶囊有 `:focus-within` 的 `background` 过渡（0.25s），motion 逐帧写内联背景会与之打架。将来新增毛玻璃元素的渐隐动画按同规则加白纱关键帧，令牌取 `--glass-veil`，不要硬编码；渐显同样在入场前铺上、随入场全程褪去。

## 页面结构与全局宽度

**全局宽度规则**：宽度由 BaseLayout 的主内容行 `.page-main` 统一执行，**页面不声明外层宽度**——桌面端 `.page-main` 最宽 `--content-width`（1200px）且横向居中，视口不足时两侧各空 `--page-gutter`（56px）；移动端（≤768px）不设最大宽度，两侧各空 `--page-gutter-mobile`（16px）。三个令牌在 `variables.css`；导航内层宽度用与 `.page-main` 完全相同的公式（全站唯一的宽度机制），左右边缘与页面内容在任何宽度下对齐（导航内容 logo + 七个链接约 640px，最窄桌面视口 769px 时内容盒 657px，放得下不折行；链接 padding 10px / gap 2px 是为七个链接收窄的）；页脚内层仍是 max-width + 左右 24px 内边距，尚未对齐。行内两列：常驻侧栏（宽 `--posts-side-w` 260px）+ `main#swup` 内容列（flex 居中）；文章区变体时内容列再收窄到 1000px（`max-width`）。内容列 `.page-main > .hero` 带 `align-self: stretch`——行内默认 `align-items: flex-start` 会让列高塌成内容高，拉伸后它纵向填满整行（行本身是 `.page` 列里 `flex: 1`、撑满视口高），首页 `.content-wrapper` 的 `margin: auto 0` 才靠这里的富余高度垂直居中（重构进行级布局时曾丢这条，首页贴顶，见 `TROUBLESHOOTING.md` #41）。侧栏顶偏移 `--posts-side-offset` 由 `posts-shell.ts` 实测「页锚（`data-posts-anchor` 的页头/面包屑条）高度 + `--posts-offset-gap`」写入行内联变量（侧栏 `padding-top` 带 400ms 过渡，与 `posts-shell.ts` 的 `EDGE_MS` 同步），CSS 里只留常见首帧的默认值（列表与文章都是 50px = 36px 锚 + 14px 间隙——两界面同值，切页时侧栏零位移；改 `.posts-page` / `.posts-article-main` 的间隙必须同步改这里，否则首帧偏移错 8px）。页面最外层元素要收窄内容列就写 `width: 100%` + `max-width`；**不要只写 `max-width` 不写 `width`**——`main#swup` 是 flex 容器，auto 宽度按内容尺寸收缩，纯中文内容的 max-content 约等于一个字宽，页面会塌成一条窄缝。首页的 `.content-wrapper` 是 `width: 100%` + 居中：桌面端左 360 + 右 340 两栏保持设计宽（不拉伸不压缩），整组在内容区内居中，828px 视口时恰好顶到两侧留白线；手机端与 769~827px 走单栏，单栏填满整盒、顶到留白线（组件级断点，同文章详情 850px 隐藏右侧目录一个先例）。

`body.is-dragging-scrollbar`：自定义滚动条拖拽态，按住滑块期间整页光标固定 `grabbing`（`ui/scrollbar.ts` 增删；`:root` 前缀抬权重压过组件 scoped 的 cursor 规则）。`body .swup-progress-bar`：swup 切页进度条的高度与颜色覆盖（元素本身由 `@swup/progress-plugin` 动态插进 body 顶部，无静态标记，见 `astro.config.ts` 的 `progress: true`）。

> 切页滑动转场没有 CSS 类（旧版的 `.edge-*` 已删）：动画由 motion 的 `animate()` 直接驱动（条带在 `posts/strip.ts` 与 `posts/transition.ts`，搜索浮层在 `posts/search-float.ts`），CSS 端只留两个左缘元素的静态端点态（位置 / 高度 / 层叠），机制见 [ARCHITECTURE.md](./ARCHITECTURE.md) 的脚本职责表。

## 全站背景（`src/assets/backgrounds/`）

背景是**方案制**的：`src/data/background.ts` 是唯一编辑点，`type` 选 `'css'` 或 `'image'`，`path` 只填文件名（不含目录），`type` 决定去 `css/` 还是 `images/` 找。

```ts
export const background = {
  type: 'css', // 'css' 用 css/ 里的样式绘制，'image' 用 images/ 里的图片
  path: 'ocean.css', // 只填文件名，写错会在构建期直接报错
  scrim: 0, // 图片压暗强度 0~1，0 为不压暗（css 方案忽略）
};
```

图片方案的**铺图方式固定、不接受配置**：高度永远撑满视口，宽度取「容器宽」与「按高度缩放后的图宽」中的较大者——视口比图片更宽时横向拉伸填满，更窄时把超出的左右居中裁掉。纹理变量（`--bg-image` / `--bg-ratio` / `--bg-scrim`）由 `Background.astro` 从图片自身读出后写到 `.bg` 元素的行内样式上，同时也挂到 `:root`（供需要复刻背景的局部效果读取，如关于页时间轴的两端渐隐）——**换图片不用改任何配置**。

机制：`astro.config.ts` 里的 `backgroundPreset` 插件在**构建期**把这个字符串翻译成字面量 import 并交给 `virtual:background` 虚拟模块。因此**只有被选中的那一个预设会进产物**，`css/` 和 `images/` 里放多少备用预设都不影响构建体积。代价是**改了 `background.ts` 要重启 `pnpm dev`**（`pnpm build` 不受影响）。

背景容器写在 `global.css`：`.bg` 是全站背景容器（`position: fixed` + `z-index: -1` + `height: 100lvh`，由 `Background.astro` 渲染，不属于任何预设）；图片方案的真实那层 `.bg--image` 带首载淡入（`is-ready`）标记；背景容器克隆 `.bg--clone`（目前只有时间轴两端渐隐用，`Timeline.svelte` 在遮罩层里放一份，跟着铺同一张图、同一套预设，`z-index: 0` 不出所在层）；铺图规则一处写给两层（`.bg--image, .bg--clone`）：用 `--bg-image`（缺省 `none`），`background-size` 取 `max(100%, 100lvh * --bg-ratio) 100%` 实现「高度撑满 + 宽度取大者」；图片方案可选压暗层强度取 `--bg-scrim`（默认 0），真实那层用伪元素、克隆层用子元素，避开预设自己的 `::before`。

预设只写 `:root` 令牌与 `.bg::before`（可选再加 `.bg::after`）伪元素，容器样式一律不动。选择器写 `.bg` 而不是 `.bg--image`，克隆层（`.bg--clone`）才会跟着同一个预设一起画——时间轴两端渐隐靠这一点与背景无缝对上。

**兜底色只在 `html` 上写一处**：`global.css` 的 `html` 写 `background-color: var(--bg-base, #000)`——**优先用预设自带的 `--bg-base`**（每个 CSS 预设在自己文件顶部的 `:root` 里声明）；图片方案不打包任何 CSS 预设，没人声明 `--bg-base`，回退纯黑与首载 loading 屏衔接。所以**换预设只改 `src/data/background.ts`，不用再回头同步 `global.css`**。

不要为「图片方案的兜底色」再加令牌或做特判：切图片方案只是临时折腾，固定纯黑兜底够用，为它引入一层通用令牌会让这套回退变复杂，不值得。

`.bg` 上**不要**再写一份底色：预设的 `::before` 自己铺的就是不透明底色，那一层本来就被盖住（实测写与不写最大差 2/255，可忽略）。**但 `html` 这处不能删**——它管过度滚动回弹时露出的画布色（手机拉到顶/底那一下）与背景渲染前的防白闪；有预设时它就是预设底色，没了它连用预设都会闪白。

**网格层怎么加**（`blueprint.css` 是范例）：线只走横竖、周期取整数倍、线端收在同一位移（`background-position` 写负的线宽，避免 1px 线跨半像素糊成两像素灰边），再加一层径向 `mask` 让线网向四周淡出。**不要用斜向亚像素条纹**，它和线网会干涉出摩尔纹。

**斜向 / 闭合图案用内联 SVG，别硬拼渐变**（`honeycomb.css` 是范例）：蜂窝这类要闭合的图形，边方向是 30° / 90° / 150°，用 `linear-gradient` 拼竖边时只能画满高竖线，切出「只占 1/3 高度」的那一段得再套遮罩，硬色标相位极难对齐，画出来会变成菱形或竖条而不是六边形。改成一格图案写成 SVG、再以 `url("data:image/svg+xml,...")` 平铺就精确得多，且仍是单文件、无图片请求。两个必须注意的点：**SVG 属性一律用单引号**（`url("...")` 的定界符是双引号，属性里再出现双引号会把 URI 提前截断，图案整个不显示且不报错）；周期常带小数（`√3·28 = 48.4974`），`background-size` 要写足精度，别四舍五入。

**高频细节是磨砂感的前提**：`backdrop-filter` 的 `blur()` 只抹得掉高频细节，对纯渐变模糊前后几乎一致。纯渐变预设（如 `ocean.css`）没有图案层，玻璃卡的「磨砂感」会弱（卡片靠 1px 内描边与统一投影 `--shadow` 保持轮廓）；带高频层的预设（`blueprint.css` 的 20px 细网格、`wave-dots.css` / `honeycomb.css` 的线网点阵）磨砂感明显。这是取舍，不是 bug。

**预设默认不含脚本、不含图片请求**（图片方案除外），各层绘制一次即静态常驻，滚动与 swup 切页都不触发背景重绘——玻璃卡的 `backdrop-filter` 采样到的始终是稳定像素。窄高竖屏（`max-aspect-ratio: 3 / 4`）重排色斑，避免渐变被拉成竖条。

**动效默认不加**：背景静态预渲染最省，滚动时不重绘也不合成。纵深与「科技感」优先用**静态手段**做——色斑层次、顶部冷光定出光源方向、四角压暗收拢视线、高低频叠加。

真要做动效，**只动 `transform` 与 `opacity`**：这两样由合成器处理，不重绘、不重新光栅化，也不用定时器。多条动效的周期取互质，错开后不会同步成一次整体的明暗闪动。

**性能红线：不要用动画平移 `background-position`。** `background-position` 是绘制属性而非合成属性，动画它意味着**每一帧都要把那几层径向渐变整块重新光栅化**，是滚动明显发卡的主因。同理别去动画 `background-size`、`filter`、`mask` 这类属性。

真的加动效时守两条约束：**位移幅度必须小于放大留出的边距**（`scale(1.05)` 只多出 2.5%，位移就得压到 ±0.9% 以内，否则放大后的边会被推进视口，露出 `html` 兜底色）；**压 `opacity` 前先确认预设底色与 `--bg-base` 同色**，否则半透明处透出来的是另一个颜色。全部动效都要在 `prefers-reduced-motion: reduce` 下停掉。

**背景铺满，不要用 mask 做暗角淡出**（`honeycomb.css` 的教训）：给线网层加径向 `mask-image` 让四角淡出后，左下、右下角会**真的一个六边形都没有**（实测四角线像素 0.00%），用户会直接看出「角落缺了」。要压边角明暗就用低频层里那层四角压暗（`radial-gradient` 的黑色渐变），不要动线网本身。

**改多层的预设时，层数与层序要能独立看懂**：`.bg::before` 的 `background` 简写逐层带注释，增删一层只影响这一条规则（各层都是整屏图幅时（如 `honeycomb.css`）可省略逐层 `background-size` / `background-position` 列表）；竖屏 / 手机端换排布时改的是简写里对应的渐变层，覆盖时**底色必须写回**（它是简写完整值的一部分，漏了底色会被清掉）。

**会持续改变背景颜色的动画最费**：`hue-rotate` 这类让色相一直在变的动画，玻璃卡的 `backdrop-filter` 每帧都要重新采样重糊，滚动时的合成开销高于静态预设——这是**用开销换观感**，`prefers-reduced-motion: reduce` 下这类动画同样要停掉。

**配色经验**：色斑不要等强度堆叠，分主次才不发闷。单色系预设要**把色相统一在一个区间**（`ocean.css` 是 214°~228° 的蓝—蓝紫），不要掺入区间外的偏绿色相（如 201° 青绿），会与整套蓝色打架。注意这条**只适用于单色系预设**：刻意走多彩路线的预设（色相横跨全环）不做色彩收敛。选预设时先确定走哪条路线，别把两套标准混用。

**排版经验**：**不要用斜向亚像素条纹**（`repeating-linear-gradient` 配 1px），它在屏幕上会和大面积线网干涉出摩尔纹，是「看着怪」的常见来源。多层图案时周期取整数倍，避免互相拍频。**要「没有形状」的彩色背景就别加图案层**：点阵、条纹、网格都会读出可辨认的形状，只用大半径径向渐变 + `blur()` 柔化边界即可（`ocean.css` 是范例）。

**加新预设**：把 `.css` 丢进 `css/`（或把图片丢进 `images/`），再把 `src/data/background.ts` 的 `path` 改成文件名即可，产物零增长。

## 首载：CSS 内联与 loading 屏

- **外链 CSS 是渲染阻塞资源**（高延迟下白屏时长 = HTML + CSS 串行等待），所以 `astro.config.ts` 的 `inlineCss()` 钩子在构建后把 head 里全部 `link[rel=stylesheet]` 内联成 `<style>`——首帧第一块 HTML 解析完即可画。**别走「preload + onload 切 rel」的非阻塞路径**：`SwupHeadPlugin` 按 `outerHTML` diff head、`awaitAssets` 只等 `link[rel=stylesheet][href]`，切 rel 后新旧标签对不上，每次切页 remove + 重加样式表、闪样式；内联 `<style>` 被 head diff 天然处理（同步生效），不碰 swup。
- **`#boot-splash` 首载 loading 屏（BaseLayout 自持）**：body 第一个元素 + head 的 `<style is:inline>` + head 顶部 `js` 类门 + body 尾部淡出脚本，自足、不依赖任何外部资源，随首帧画出；等 `window load` 揭幕（最少 500ms、5s 超时兜底），揭幕推迟到页面资源就绪，用户揭开后看到的是加载完整的页面；`prefers-reduced-motion` 下动画全停。**这块必须自足**：首帧只能依赖它自己，颜色与时长全是局部值，唯一例外是背景底色 `var(--bg-base, #000)`（CSS 预设取预设底色衔接、图片预设回退纯黑）。
- **背景图**：`Image` 预热走缓存，就绪后给 `.bg--image` 加 `.is-ready` 自行 0.8s 淡入（`prefers-reduced-motion` 不淡入直接显示）；兜底超时路径（图未就绪）下背景图到位后自行淡入，不 pop。
- **怎么确认**：构建后 `dist/**/*.html` 搜 `link rel="stylesheet"` 0 命中；`dist/index.html` 的 body 第一个元素是 `#boot-splash`。

## 新增 CSS 的规则

1. **高频复用的元件**（卡片/按钮/输入框这种积木）写 `utilities.css`；**后台专属**的写在 `src/assets/css/admin/`（布局进 `admin.css`、元件进 `elements.css`）；**页面内容排版**（标题/描述/座右铭）写各页 `<style>` 或页面组共享文件；组件私有的写在组件 `<style scoped>` 里
2. **新变量**：全站用的写 `variables.css`，后台用的写 `admin/variables.css` 的 `:root`，命名用 `--xxx` 前缀
3. **骨架屏相关**写在 `shared/skeleton.css`
4. **文章列表共享样式**写在 `posts/posts-listing.css`
5. **全站背景**改 `src/data/background.ts` 一处即可；预设写在 `src/assets/backgrounds/` 下，别在组件里另起背景层
6. **命名**用 BEM 风格或简短语义名，避免和组件样式冲突
7. **要悬停效果就给元素挂 `.hoverable`**，不要在组件里另写 `:hover` 定白底/描边色；浓淡统一改 `variables.css` 的 `--hover-*`。挂 `.hoverable` 的元素**不要自己写 `transition`**（会盖掉全站悬停过渡，见「悬浮反馈」）
8. **悬停提亮的过渡时长一律写 `var(--t-hover)`**（`variables.css`，全站悬停提亮时长的唯一来源），不要在各处硬编码 `0.15s` / `0.2s` / `0.25s` 这类时长；位移 / 开合 / 显隐 / 图片缩放等其他动效仍各自定
